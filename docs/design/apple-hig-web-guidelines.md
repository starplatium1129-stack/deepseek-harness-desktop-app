# 基于 Apple HIG 的 Web 产品设计规范

**版本：** 1.1（仓库入库版）  
**资料核对日期：** 2026-09-14  
**适用范围：** 内容型网站、工具型 Web 应用、创作工作台与 Electron Web 界面。  
**文档性质：** Apple 官方原则摘要 + Web 无障碍标准 + 项目化建议，不是 Apple 官方规范的完整译本。

> 核心目标：让内容成为主角，让操作容易理解，让状态可信，让视觉语言保持一致。
>
> 本文由 1.0 对话交付稿整理入库，保留通用规则，并以当前 GitHub 仓库更正旧项目附录。**HUIYU 当前支持深浅双主题，不再采用旧稿“唯一深色主题”的约束；DeepSeek 桌面端不继承 HUIYU 的角色、粉色与画室品牌。** 本次入库不修改运行时 UI，也不代表现有实现已经通过验收。

## 0. 如何使用这份规范

### 0.1 三种依据

**官方原则**来自 Apple Design、Human Interface Guidelines（HIG）及官方设计讲解，引用为 [Axx]。**Web 标准**来自 W3C WCAG 2.2 与 WAI-ARIA APG，引用为 [Wxx]。**项目建议**包括本文提供的尺寸、间距、组件约束和实施顺序；除明确标注外，不是 Apple 的跨平台固定数值。

### 0.2 规则强度与冲突处理

“必须／不得”表示采纳后的验收要求；“应／优先”表示默认做法，偏离时记录原因；“可”表示有明确收益时使用。保存本文并不自动替换项目已有的品牌、平台范围或设计变量。

冲突处理顺序：**真实性与数据安全 → 无障碍与可用性 → 已确认的产品定位和品牌边界 → 现有共享组件与令牌 → 本文建议默认值。** 品牌不能成为降低可读性或隐藏关键操作的理由。

### 0.3 平台边界

Apple HIG 面向 Apple 平台，不是所有网站必须长成 iOS 的要求。本文抽取可迁移原则，不覆盖 Apple Watch、Apple TV、空间计算、CarPlay 等完整平台规范。[A01][A02]

Apple 按钮指南的一般命中区域建议是至少 44×44 **pt**，并对 visionOS 使用更大的建议值。Web 的 CSS px、CSS pt 和 Apple 平台布局 pt 不能混为一谈；本文的 44×44 **CSS px** 是独立的 Web 项目建议。[A07]

### 0.4 两个项目的适用边界

| 项目 | 保留的现有约束 | 本文的角色 |
|---|---|---|
| 绘遇 · HUIYU | 角色与故事创作画室；深浅双主题；角色强调色；图像优先；根目录 DESIGN.md 是设计真相源 | 通用评审依据，已采纳规则回写 DESIGN.md 与共享设计系统 |
| DeepSeek Harness Desktop | Windows 桌面习惯；上游 Harness 工作空间；classic/glass 预设；light/dark/system；现有动效与材质模块 | 审查桌面壳与适配层，不要求苹果原生外观，不移植 HUIYU 品牌 |

第 14 节按项目分别适用。第 16 节是通用实施说明，不得把一个项目的专属规则自动扩散到另一个项目。原生操作系统行为、上游界面与桌面自定义界面的验收证据须分别记录。

## 1. Apple Design 网站应该怎样理解

Apple Design 是一套资源入口，而不是单一视觉模板。[A01][A11]

| 资源 | 解决的问题 | 项目中的用途 |
|---|---|---|
| HIG | 信息组织、组件行为、交互预期 | 决策原则和设计评审依据 |
| Apple Design Resources | 平台界面与图标的准确设计 | 原生 Apple 项目参考，不机械搬进 Web |
| 字体、SF Symbols、Icon Composer 等 | 字体、符号与应用图标的协调 | 理解一致性；采用资源前核对使用条款 |
| 官方设计视频 | 设计意图与推导过程 | 避免只模仿截图 |

先确定用户任务，再选择信息结构与组件，最后决定视觉表现。不要先规定“必须玻璃化”，再让功能迁就材质。

## 2. 核心设计原则

HIG 首页强调以下原则；右栏是本文的 Web 转译，而不是要求复制 Apple 外观。[A02]

| 原则 | 含义 | 执行规则 |
|---|---|---|
| Hierarchy／层级 | 控件和界面使内容层次更清楚 | 内容、导航、主操作、辅助信息不能全部同等醒目 |
| Harmony／协调 | 形状、边距与环境相协调 | 相邻组件属于同一视觉家族，圆角与内边距有关系 |
| Consistency／一致性 | 遵循惯例并适应显示环境 | 同一行为使用同一组件，窗口变化不改变功能含义 |

进入页面后，应能判断“我在哪里”“最重要的内容是什么”“接下来能做什么”“当前发生了什么”。不能依赖先读帮助文档才能识别主任务。

每个独立任务区域默认只有一个视觉主操作；其他动作通过次要样式、位置和分组保持可发现。复杂页面的独立任务区域可以各有主操作，不要求全局只能出现一个按钮。

装饰必须能解释用途：表达关系、强调状态、帮助阅读或建立品牌识别。“看起来高级”不足以成为增加模糊、阴影、渐变或动画的理由。

## 3. 信息架构与导航

Apple 布局指南强调重要性排序、对齐、关联分组和渐进披露，布局需要适应实际可用空间。[A03]

导航回答“去哪里”，动作回答“做什么”。“作品库”“设置”属于目的地；“生成”“保存”“删除”属于操作，不应混成同一级导航。

一级导航应短而稳定，当前目的地清楚可辨。位置变化、刷新、浏览器前进／后退不能无故丢失可恢复的导航上下文。

收藏、预览、筛选与详情靠近作用对象。高级参数和诊断默认折叠，但不得隐藏费用、破坏性后果、必填项、错误原因或恢复入口。

| 页面类型 | 主体区域 | 辅助区域 | 应避免 |
|---|---|---|---|
| 阅读／展示 | 正文、作品、核心信息 | 简短说明与相关操作 | 装饰挤压正文或作品 |
| 列表／发现 | 结果、条目、作品网格 | 搜索、筛选、排序 | 先理解内部分类体系才能查找 |
| 创作／编辑 | 画布、编辑区、生成结果 | 参数、素材、任务状态 | 参数和日志成为视觉主角 |

设置按用户理解的任务或对象分组，不照搬后端模块名称；高风险操作与普通偏好设置分区。

保留合理的筛选、滚动位置、选中对象和编辑草稿。返回列表不等于重置列表，打开设置不等于清空工作状态。产品明确状态保留范围与期限，不暗中承诺永久保存。

## 4. 布局、间距与响应式

本节数值为 Web 建议值。已有项目先复用自己的间距系统，不并行创建第二套近似值。

| 尺度 | 建议值 | 常见用途 |
|---|---:|---|
| 极小／小 | 4／8px | 图标、微间距、紧密关联元素 |
| 中／常规 | 12／16px | 相关表单项、默认内容间距、窄屏外边距 |
| 大／分组 | 24／32px | 卡片内边距、相邻分组与模块 |
| 章节／大章节 | 48／64px | 主要区段；不滥用于密集工具页 |

组内距离通常小于组间距离。间距表达信息关系，不用于机械填满页面。

普通信息页可从 1200px 内容最大宽度起步；阅读区单独限制行宽。创作工作台可使用可用视口宽度，至少 16px 外边距作为起点。标题、正文、列表、表单优先使用共享起始线；不以随意居中掩盖对齐问题。多语言产品另验不同语言长度与阅读方向。

按容器能否容纳内容切换布局，而不是只判断设备名称。[A03]

| 可用空间 | 布局策略 | 交互要求 |
|---|---|---|
| 窄 | 主内容优先，辅助面板折叠或改抽屉 | 主要操作可触达，不依赖悬停 |
| 中 | 主内容加一个辅助区域 | 侧栏不能挤压到主内容不可用 |
| 宽 | 必要区域并排 | 额外空间优先给内容，不默认展开更多参数 |

不得靠整体缩小字号和按钮适配窄屏。文字增大时允许换行、容器增高和横向分组转纵向。固定工具栏为正文与焦点预留空间；安全区、软键盘、横屏、短窗口都需验收。

## 5. 字体与排版

Apple 强调可读性、层级、有限字体家族和文字尺寸适应。不同平台默认字号不同，不能把 iOS 的 17pt 当成所有网站规则。[A04]

| 角色 | Web 建议字号 | 建议字重 | 建议行高 |
|---|---:|---:|---:|
| 页面标题 | 28–36px | 600–700 | 1.2–1.35 |
| 区块标题 | 20–24px | 600–700 | 1.3–1.45 |
| 正文 | 16px | 400 | 1.6–1.8 |
| 表单标签／按钮 | 14–16px | 500–600 | 1.4–1.5 |
| 次要说明／元数据 | 13–14px | 400–500 | 1.45–1.65 |

这些是起点，不是固定尺寸或 WCAG 的字号下限。紧凑桌面界面采用更小字号时，应记录场景理由，并验证可读性与缩放。重要说明不能因为叫“辅助文字”就无限缩小。优先相对单位，保留用户缩放能力。

正文使用适合中文的已有无衬线字体栈；等宽字体用于代码、路径、种子、模型标识等精确文本。不为“苹果感”替换整个品牌字体系统。

关键状态不能只靠字重区分。正文、参数、错误、按钮不使用装饰性渐变。字符裁切仅用于有补充完整读取方式的次要信息，不能截断关键按钮、错误原因或确认后果。

文字放大到 200% 时，内容和功能不丢失。一般纵向阅读内容验证 320 CSS px 重排；必要二维画布或数据表允许局部二维滚动，外围说明与操作仍要可用。[W05][W06]

## 6. 颜色与品牌表达

颜色用于沟通、品牌和状态；同一种颜色含义保持一致，系统语义色不随意改作其他用途。[A05]

| 角色 | 用途 | 规则 |
|---|---|---|
| 页面背景／内容表面 | 稳定基底与分组层级 | 不抢内容，不要求每层带阴影 |
| 主文字／次文字 | 信息层级 | 次文字仍满足适用对比度 |
| 主交互色 | 主操作、当前选择、必要强调 | 不把所有标题、图标和卡片染成主色 |
| 成功／警告／危险／信息色 | 系统状态 | 同时配文字或图标，不能只靠颜色 |
| 边界／焦点色 | 可操作边界与当前位置 | 焦点不等于悬停 |

颜色按语义命名，不按单页命名。必须复用共享令牌；需要扩展时先明确角色，不随手加近似色。

品牌通过主色、字体气质、图像选择、文案、构图和少量标志性细节建立。功能含义、错误处理和键盘行为不能为品牌变得陌生。

Web 不因参考 Apple 就必须增减主题。主题数量是产品决策；所有已支持主题均须验收。原生 Apple 应用另按系统材质与自适应颜色指南处理。[A05]

## 7. 材质、层级、圆角与阴影

### 7.1 Liquid Glass 的边界

Apple 将 Liquid Glass 主要用于内容上方的导航与控制层，不无差别铺到普通内容层，并要求克制使用；内容层仍可用标准材质，部分短暂交互控件有例外。[A06]

Web 不必模拟真实折射，也不能把一条 CSS 模糊称为完整复现 Apple Liquid Glass。

| 场景 | 建议 |
|---|---|
| 顶部导航、浮动工具、媒体控制 | 有上下文收益时使用克制半透明 |
| 正文、表单、密集参数、错误详情 | 稳定可读的实体或高不透明度阅读表面 |
| 嵌套卡片与弹层 | 不叠多层高透模糊制造层级 |
| 高对比、降低透明度、效果失效 | 预先定义实体背景，保持信息与交互 |

基础样式在无透明效果时仍成立。减少透明度偏好作为渐进增强，可读性不能依赖检测是否成功。壁纸与图片变化后重新检查实际显示背景。

### 7.2 形状与深度

同组圆角、图标笔画、控件高度和内边距协调。紧凑控件、卡片与标签可有不同形状，但差异对应角色。已有项目沿用圆角令牌。

嵌套轮廓可从“内圆角约等于外圆角减去内缩距离”开始，再做光学检查；不是固定半径要求。Apple 官方讲解也强调同心关系及不同密度下的形状选择。[A12]

药丸形适用于筛选、状态标记、分段控件等，不因此把所有输入框和容器做成胶囊。静态内容通常不需悬浮阴影；交互表面可有轻反馈；弹出内容通过位置、表面与遮罩建立层级。

弹窗、菜单、提示和固定工具使用统一层级管理，不用单页不断抬高 z-index 修补。真正模态阻止背景交互，普通局部工具不无故模态化。

## 8. 组件规范

### 8.1 按钮与状态

按钮清楚表达用途，包含按下反馈；用视觉样式而非任意尺寸差异强调同组首选动作。[A07]

| 类型 | 用途 | 表现 |
|---|---|---|
| 主按钮 | 继续、生成、保存 | 主交互色；同任务区默认一个 |
| 次按钮 | 调整、查看、返回 | 中性、描边或弱填充 |
| 文本按钮 | 低优先级且含义明确的辅助动作 | 仍可识别、可聚焦、可读 |
| 危险按钮 | 删除、覆盖、数据损坏风险 | 危险语义与明确文案，不作安全默认动作 |

同组按钮协调高度、圆角、基线。用“保存作品”等明确动词，重要或陌生动作不只显示图标。

触屏建议实际命中区至少 44×44 CSS px；扩大热区不得重叠。桌面紧凑控件可以更密，但须满足适用 Web 目标尺寸与键盘要求。32px 桌面按钮不因未达到触屏建议就自动判定不合格。[W03]

组件按行为覆盖相关状态：默认、悬停、键盘焦点、按下、选中／开启、禁用、忙碌、校验错误。静态卡片不硬加无意义状态。选中与焦点、忙碌与焦点等可以组合，示例必须覆盖相关组合。

悬停不能是唯一入口；焦点与选中分开表达；按下立即反馈；关键禁用场景解释原因；忙碌防重复提交且不误报成功；错误对应具体字段或任务并提供恢复方式。

### 8.2 输入与表单

输入有持续、关联的标签，placeholder 只作例子。必填、格式与限制输入前可知；错误在字段附近说明，必要时提供摘要。

校验不在尚未完成输入时持续打断。提交失败保留已填内容。自动保存与显式保存区分，“已保存”来自真实成功。多步骤可安全返回；离开时说明未保存修改的后果，危险信息不能藏进高级设置。

### 8.3 卡片与列表

卡片边界表达真实分组、对象或选择单元。可点击与静态卡片行为清楚；多个动作不因整卡事件互相冲突。作品优先展示预览、标题和重要说明，技术标签次要。

搜索条件靠近结果，筛选可移除。首次空白、搜索无结果和加载失败不能共用“暂无数据”。

### 8.4 弹窗、抽屉与提示

模态用于短任务、重要后果确认或阻断问题；长篇编辑用独立页面或足够空间，避免层层弹窗。

模态打开时焦点进入，Tab 内部循环；Escape 关闭或进入安全退出处理；关闭后通常返回触发点。破坏性确认优先聚焦安全选项。[W04]

普通成功可用局部或短提示。需要用户处理的错误不得只有自动消失的消息；应持续保留原因与恢复入口，直至处理或主动关闭。

## 9. 加载、生成、失败与恢复

Apple 区分可确定与不可确定进度，能可靠量化时报告真实进度，不制造误导完成感。[A09]

| 状态 | 展示 | 可用动作 |
|---|---|---|
| 未开始 | 任务说明、必要输入、开始入口 | 开始 |
| 提交中 | 请求正在提交 | 防止重复 |
| 排队中 | 已入队；位置仅在真实可得时显示 | 支持时取消或继续其他工作 |
| 执行中 | 真实进度或明确阶段 | 查看结果，支持时取消 |
| 取消请求中 | 已请求、尚未确认 | 等待真实结果，不宣称已取消 |
| 连接异常／状态未知 | 暂不能确认任务结果 | 获取状态，避免直接重复生成 |
| 失败 | 失败位置、影响、输入是否保留 | 重试、修正或诊断 |
| 已取消 | 服务端已确认停止或撤销 | 重新开始 |
| 完成 | 可访问的实际结果 | 保存、比较或下一步 |

按实际能力选用，不要求所有产品拥有相同状态。无法可靠获取百分比时显示真实阶段，不用计时器伪造 0–99%。失败、超时、断线和服务端继续运行不是同一件事。

新任务应保留上一份成功结果，直到新结果可用或用户明确删除。仅停止前端等待时，明确服务端任务可能继续。可能重复计费或生成的请求共同防重；重试先确认现有任务状态，不把网络超时当作未执行。

关键动态状态可被辅助技术感知，不因每次百分比变化持续打断。[W08]

错误推荐结构：“发生了什么 + 哪些内容不受影响 + 可以做什么”。例如“连接中断，暂时无法确认生成状态。你的输入已保留。请重新获取任务状态，避免重复提交。”只有确实保留输入时才能这样表述。不能把安慰性文案当成数据保护。

## 10. 动效与反馈

动画要有用途、反馈简短、方向符合预期，不迫使用户等待结束才能继续操作。[A08]

时长与运动模型复用项目现有系统。HUIYU 可沿用其 150ms／240ms 语义时长；DeepSeek 桌面端可保留已实现的连续弹簧模型。这些都是项目实现，不是 Apple 统一参数。

按下、展开、关闭、切换、完成动效服务于因果关系；位置与方向可理解，高频操作不增加重复演出。可中断动画不能导致旧目标覆盖新操作。

必须处理减少动态效果：终止或收敛正在进行的运动，保留静态文字、状态图标、进度语义；不能只停止旋转让任务看起来冻结。装饰不夺取焦点、截获点击或降低对比度；静态角色图片不周期缩放、摇摆或漂浮来假装活动。

## 11. 无障碍验收底线

Apple 强调信息可感知、交互直观、适应不同能力和偏好；Web 还需按具体标准检查，不能凭外观断言支持无障碍。[A10]

| 项目 | 规则 | 依据 |
|---|---|---|
| 普通文字 | 对比度至少 4.5:1 | WCAG 1.4.3，[W01] |
| 大号文字 | 至少 3:1；通常至少 24 CSS px 常规字或约 18.67 CSS px 粗体字 | WCAG 1.4.3，[W01] |
| 必要非文字信息 | 识别控件和状态所必需的信息与相邻色至少 3:1；不包含所有装饰线 | WCAG 1.4.11，[W02] |
| Web 指针目标 | AA 基线 24×24 CSS px，有间距、行内等例外；触屏另建议 44×44 | WCAG 2.5.8，[W03] |
| 文字放大 | 200% 时不丢失内容与功能，按标准处理例外 | WCAG 1.4.4，[W05] |
| 重排 | 一般纵向内容在 320 CSS px 可用；必要二维内容按例外处理 | WCAG 1.4.10，[W06] |
| 焦点与遮挡 | 键盘焦点可见，不被作者创建内容完全遮挡；项目进一步优先完整可见 | WCAG 2.4.7／2.4.11，[W09][W07] |
| 键盘操作 | 主要功能可用键盘完成，运动路径依赖按标准例外处理 | WCAG 2.1.1，[W10] |
| 控件语义 | 名称、角色、状态、值可识别，优先正确语义的原生控件 | WCAG 4.1.2，[W11] |
| 模态焦点 | 进入、循环、退出与返回有明确行为 | APG，[W04] |
| 动态状态 | 不必强抢焦点即可被辅助技术识别 | WCAG 4.1.3，[W08] |

真正不可用控件的文字存在 WCAG 对比度豁免。HUIYU 的 disabled-text 与不使用整控件 opacity 是主动采用的更高可读性约束，不应误称 WCAG 要求全部禁用文字达到 4.5:1。[W01]

还须检查图片替代文本、真实键盘流程与减少动态效果。此表是重点清单，不是 WCAG 2.2 全部 A／AA 条款；通过此表不能自动宣称全面符合或获得认证。

## 12. 内容、图像与品牌文案

图像保持真实比例，不拉伸主体。浏览裁切有明确规则，作品审阅提供完整构图。加载前预留尺寸，失败使用稳定替代状态。

装饰与有意义内容区分；品牌装饰不进入阅读顺序，不承担唯一操作含义。

文案清楚直接、不责备用户。创作页可温柔、具有角色感；错误、队列、模型与恢复动作必须准确。不要把“连接失败”写成无法判断问题的诗句。

对未知状态如实说明，不虚构预计时间、队列位置、保存结果或成功反馈。

## 13. 工程落地与设计治理

变量按“基础尺度 → 语义角色 → 组件使用”组织。一个语义角色一份定义，颜色、圆角、阴影、间距与时长集中管理；页面只组合。

新增组件先检查是否可复用。扩展时补齐用途、状态、键盘、响应式与示例，不只交默认态视觉稿。

交付最小集合：页面任务、默认和异常状态、桌面及窄屏表现、共享变量、键盘行为、溢出规则、验收结果。风险操作另写取消、失败与恢复策略。

改造顺序：先修无法操作、数据风险、状态失真、明显不可读；再统一导航、标题、按钮、输入与状态；随后布局、分组与响应式；最后材质、阴影、动效。不能只美化单页制造视觉孤岛。

验证区分源码检查、隔离测试、真实界面与分发包验收。测试存在不等于本次运行通过；检查桌面壳不等于上游整个工作空间通过。

## 15. 发布前验收矩阵

| 场景 | 通过条件 | 优先级 |
|---|---|---|
| 首次进入 | 可识别目的、主内容、首个有用操作 | 重要 |
| 完整任务 | 开始、处理、完成、失败、取消／退出清楚 | 阻断 |
| 重复点击与断线 | 不重复提交或误报；未知不等于失败 | 阻断 |
| 键盘流程 | 主功能可完成，焦点可见，模态不泄漏 | 阻断 |
| 文字与控件对比度 | 在真实背景下满足适用标准 | 阻断 |
| 200% 文字／页面缩放 | 信息、操作、恢复入口不丢失 | 阻断 |
| 窄屏重排 | 不意外整页横滚，必要二维内容局部处理 | 重要 |
| 短窗口／软键盘／固定工具栏 | 操作与焦点不被遮挡 | 阻断 |
| 无图片、长标题、空结果 | 布局稳定，解释与下一步明确 | 重要 |
| 减少动画／实体降级 | 状态清楚，功能完整 | 阻断 |
| 一致性 | 同类组件角色、尺寸、状态、命名一致 | 重要 |
| 品牌 | 内容仍为主角，不成为仿制界面 | 重要 |

采用本规范后，阻断项不得仅以视觉评分高放行。范围以实际支持功能为准；没有取消能力时，验收准确说明，而非伪造能力。

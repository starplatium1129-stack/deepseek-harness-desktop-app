# ZCode 新会话验证失败：反馈草稿

日期：2026-09-13。仅为本地草稿，未向外部发送。反馈入口参见 [ZCode 官方反馈说明](https://zcode.z.ai/cn/docs/feedback)。

## 环境与现象

- Windows 11（26100），ZCode 桌面 3.11.2，内置 CLI 0.16.5。
- 用户实际使用的模型与套餐：GLM 5.3 Flash／体验套餐。
- 既有普通会话此前能够回复；在当前原版窗口手动新建同模型会话后，用户确认也不能直接回复。
- 协作使用原版程序和原版用户资料，没有复制登录文件，也未替换模型 API 或验证码实现。
- 显式请求 `builtin:zai-start-plan/GLM-5.3-Flash`，原生 accepted、turn.started 均已收到；原生错误归因确认 provider/model 与选择一致。
- 原版滑块验证出现后，用户手动操作仍收到失败。原生 SDK 最后报告 `Captcha verification timed out after 120000ms.`，外层错误为 `model_request_failed`，`retryable=false`。

## 期望与实际

期望：原版窗口内手动验证通过后，新会话能够开始模型请求。

实际：手动验证失败，新会话未得到模型回复；协作测试没有文件改动。没有继续自动刷新、重发或重复尝试验证。

## 已排查

- 修复协作省略模型时误选列表首项 GLM-5.3 的问题；本次失败已明确发生于 Flash。
- 采用原版 deferred 会话创建、原生运行时模型解析与 V4 发送流程。
- 原版工作区验证组件和监听保持原样，协作只观察任务状态。
- 独立资料与原资料的失败分开记录，不能将独立资料结果冒充原资料验证。

需要官方协助确认新会话的验证失败原因。可由用户从应用内报错条的“反馈问题”进入并按需附诊断日志；本草稿没有收集或附带账号、密钥、Cookie、验证码图像或完整会话日志。

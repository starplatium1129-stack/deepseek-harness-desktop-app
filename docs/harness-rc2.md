# Harness 0.1.5-rc.2 接入

2026-09-13 核对 npm：`latest` 仍为 `0.1.5-rc.1`，`next` 为 `0.1.5-rc.2`。此前仅查询 latest，导致 RC 用户漏报更新。上游发布说明见 [rc2](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.5-rc.2)。

## 更新策略

当前核心已在 RC 时，检查 latest 与 next 中同一 major/minor/patch 的后续 RC，选择较新的候选；正式发布优先于同系列 RC。稳定版本用户不自动加入预览渠道，RC 用户也不自动跨入其他版本系列或 alpha。只在用户检查 / 下载时查询，不改变日常启动的版本锁定。

0.2.5 内置锁更新到 rc2，并记录完整 npm 依赖锁。prepare-runtime 从仓库锁读取准确版本；磁盘运行时版本或锁不匹配时通过 npm ci 准备，不再把缓存中的旧锁反写到仓库。旧本地运行时已保存在 `.test-data/runtime-before-rc2-*`，未修改安装版或用户数据。

新安装使用内置 rc2；已有安装的独立核心版本仍由 runtime-state 管理，不会仅因桌面包变更强制覆盖。用户可在新版桌面管理页检查、下载验证后重启应用核心更新，过程中备份数据并保留回退。

## 兼容验证

- 用独立用户临时目录运行真实 npm 下载与 SHA-512 校验，从 rc1 切换到 rc2，通过本地 Web 认证健康检查及退出验证。
- 将隔离测试历史复制到升级目录，更新后 3 个会话 / 6 轮 / 25200 tokens 保持一致，配置读取与用量 IPC 正常。
- rc2 原生插件验证通过：桌面协作桥认证、地区错误两次重试、每次尝试经过中间件、实际 web_search 引用以及退出时桥接资源清理。
- 本地固定 LLM 的标准会话交互用于分发态端到端验收，不使用真实模型额度；不能据此宣称实际付费模型兼容性已全部验收。
- 52 项相关测试覆盖候选版本选择、失败回退、数据保留及用量 / 价格 / 图表数据逻辑。
- 0.2.5 的 Windows 分发目录以全新隔离数据启动，完成本地固定 LLM 会话、历史读取、价格同步、小时图提示与筛选、图例开关、会话跳转和窄窗口检查；安装包已生成，尚未替换当前运行中的安装版。

仓库盘的独立旧测试目录不能设置所需 Windows DACL，最初探测因此失败；更新验收脚本已改用用户临时目录，不放宽权限。生产用户数据目录仍保持原有受保护策略。

验收入口：`DSH_UPDATE_FROM=0.1.5-rc.1`、`DSH_UPDATE_FIXTURE=<独立 usage-test 目录>` 配合 `node scripts/update-smoke.cjs`。`scripts/integration-smoke.cjs` 可用 `DSH_SMOKE_RUNTIME_ROOT` 指定候选运行时目录。
